# 방법

## 문제 설정

신청서 · 등록부의 이름 · 생년월일 · 주소처럼 **정답이 이미 DB에 있는** 손글씨 값을 읽는 일은 "글자를 새로 쓰기"보다 "DB의 어느 레코드인지 맞히기"에 가깝다.
생성형 OCR은 한 글자만 틀려도 레코드가 틀리고, 필드가 길고 칼럼이 많을수록 오류가 쌓인다(글자 정확도 p, 글자 수 n이면 대략 pⁿ).
이 저장소는 DB를 인식 과정 안으로 넣는 두 방법을 다룬다.

## 1. 위치 정렬 레코드 검색 모델 (`formrec.retrieval`)

칼럼 이미지 묶음과 DB 레코드 문자열을 같은 공간에서 비교해, 글자를 생성하지 않고 정답 레코드를 고른다. 가중치 하나로 세 단계를 수행한다.

```
칼럼 이미지들 ──► 이미지 인코더 ──► 공용 쿼리 16개 ──► 이미지 벡터 ─┐
                  (세로 8줄 보존)                                 ├─► ① 벡터 검색(행렬곱 1번, 상위 K)
DB 레코드 ──────► 텍스트 인코더 ──► 공용 쿼리 16개 ──► 레코드 벡터 ─┘        │
                  (자모 · 숫자 · 영문 단위)                                    ▼
                                                    ② 위치 정렬 비교 + 글자 검증(CTC) 재채점
                                                                              ▼
                                                    ③ 칼럼별 수락 판정(자동 처리 / 사람 확인)
```

- **이미지 쪽**: 64×1280 칼럼 이미지를 보폭 합성곱으로 줄이되 세로 8줄을 평균하지 않고 채널로 접어 열 토큰 320개로 만든다(작은 글자 · 획 보존). 칼럼 이미지가 여러 장이면 토큰을 이어 붙이고 이미지 번호를 더한다.
- **텍스트 쪽**: 한글 음절은 초 · 중 · 종성 자모로, 그 밖은 글자 단위로 나눈다(세 데이터셋 공용 단위 사전). 토큰마다 칼럼 번호 · 칼럼 안 글자 순번 · 자모 역할을 더한다.
- **공용 쿼리**: 칼럼마다 슬롯을 정하지 않고 16개 쿼리가 역할을 스스로 나눈다 → 칼럼 수 · 종류 · 누락 · 배치(이미지 여러 장 / 한 줄)를 몰라도 되는 **멀티 칼럼 일반형**. 검색 점수 = 슬롯 코사인 평균 = 1,024차원 벡터 내적.
- **위치 정렬 비교기**: 문자열과 필기는 같은 순서로 진행하므로, 텍스트 토큰은 그 칼럼 이미지의 예상 위치 근처 열 토큰하고만 비교한다.
- **수락 판정**: DB 밖 사람의 최근접 후보는 대부분 한 칼럼 · 한 글자만 다르다. 칼럼별 최소 점수를 보는 작은 머리가 "거부"를 직접 학습한다.
- **학습**: 1단 대칭 InfoNCE + 2단 교차 엔트로피(정답 · 합성 음성 3개 · 배치 안 1단 최상위 12개) + 글자 인식 CTC + 슬롯 다양성 + 수락 판정.
  합성 음성 = 글자 1개 치환 · 토큰 1개 교체 · 칼럼 교체(한 글자 · 한 칼럼만 다른 어려운 음성). 이미지 인코더와 인식 가지는 세 데이터셋 train으로 CTC 사전학습한 가중치에서 시작.
- **추론**: DB는 미리 벡터로 바꿔 두고, 행렬곱 1번 + 후보 K개 정밀 비교. K · 글자 검증 가중치 · 확신도 종류 · 임계값은 tune에서 정한다.

## 2. 검출 없는 키 조건부 KIE + 레코드 단위 DB 검증 (`formrec.kie`)

```
서식 페이지 전체 + "KIE: 이름, 주소" ──► 파인튜닝 VLM ──► "이름: …\n주소: …"
                                                      │
                                    요청 키를 한 레코드로 묶어 DB와 대조(편집 거리 합 최소)
                                                      │
                          칼럼 간 상호 보정(한 칸 오독을 다른 칸이 바로잡음) ─► 확신도로 자동 처리 판정
                                                      │
                                     DB 1등과 거리가 멀면 VLM 출력 그대로(DB 밖 사람)
```

- **입력**: 서식 페이지 전체(흰 여백만 제거). 칸 검출 · crop · 라벨 위치를 쓰지 않는다.
- **키**: 이름 · 생년월일 · 주소 · 시도 · 시군구 중 1~4개, 조합과 순서를 무작위로. 키 이름만 프롬프트로 준다.
- **VLM**: PaddleOCR-VL-1.6, OvisOCR2를 같은 데이터로 파인튜닝, val loss로 에폭 선정.
- **레코드 DB 검증**: 요청된 키 값을 한 레코드로 묶어 DB 레코드와 편집 거리 합이 최소인 것을 찾는다(키별 독립 조회보다 강함).
  평가용 DB = 실제 인물 레코드 + 사람마다 한 글자 · 한 토큰만 다른 어려운 이웃 6개.
- **진행 중**: 인쇄 항목명을 키로 쓰는 일반형 데이터(`formrec.kie_general`, 표 칸 구조로 항목명–값 짝 구축, '[없음]' 네거티브, 처음 보는 서식 분할),
  우도 기반 레코드 검증(DB 후보마다 VLM 교사 강제 로그 우도로 선택, 자유 생성과의 우도비로 DB 밖 판정).

## 평가 원칙

- 분할: train(학습) / val(에폭 선정, loss만) / tune(하이퍼파라미터 · 임계값) / test(마지막 1회). 공식 평가 폴더 = test.
- 비교군도 같은 train으로 파인튜닝하고, 모든 방법에 같은 선정 규칙을 적용한다.
- 주 지표 = 레코드(질의) 완전 일치와 정밀도 99%에서의 자동화율. 보조 지표(정밀도 99.9%, DB 밖 오수락 등)도 함께 계산한다.
- 학습 · 평가를 시작할 때 실제 입력 그림 · 학습/추론 모드 출력 길이를 한 번 점검한다(`formrec.common.input_check`).
